## 1. 文档说明

### 1.1 目的
定义 IM 即时通讯产品的功能范围、业务流程、交互要求与非功能需求，作为设计、开发与验收的统一依据。

### 1.2 读者
产品、设计、前端、后端、测试、运维人员。

### 1.3 名词解释
| 名词 | 说明 |
| --- | --- |
| 会话（Conversation） | 单聊或群聊的对话容器，包含双方或多方成员 |
| 消息（Message） | 会话中的一条记录，含类型、内容、状态 |
| 已送达（Delivered） | 消息已推送到接收端 |
| 已读（Read） | 接收端已打开会话并阅读 |
| 在线状态 | 用户当前是否保持 WebSocket 长连接 |

## 2. 项目背景与目标

### 2.1 背景
构建一款对标微信的即时通讯应用，覆盖基础 IM 能力，验证 uniapp + TP6 + Workerman 技术选型，并作为可商用产品的基础。

### 2.2 产品目标
- G1：跑通「注册登录 → 加好友 → 单聊/群聊 → 实时收发」完整闭环。
- G2：消息实时性体验良好（端到端延迟目标 < 1s）。
- G3：一套 uniapp 代码兼容小程序 / H5 / App。
- G4：架构可扩展，支持二期朋友圈、音视频通话等能力。

### 2.3 阶段规划
- **一期（P0）**：核心 IM 能力（本 PRD 覆盖范围）。
- **二期（P1）**：音视频通话、朋友圈、表情包、文件传输、消息撤回、@、消息搜索。
- **三期（P2）**：转账、公众号等扩展能力。

### 2.4 目标用户
移动端个人用户，进行点对点及群组即时沟通。

## 5. 业务流程

### 5.1 注册登录
```
注册（手机号+密码）→ 后端校验 → 创建账号 → 返回 Token
登录（手机号+密码）→ 校验 → 签发 Token → 建立 WebSocket 连接
退出 → 断开连接 → 客户端清除 Token
```

### 5.2 添加好友
```
用户A 搜索手机号/昵称 → 找到用户B → 发送好友申请
用户B 收到申请 → 同意/拒绝
同意 → 建立双向好友关系 → 双方刷新好友列表
```

### 5.3 单聊消息收发
```
用户A 发送消息 → 本地展示「已发送」
→ 客户端经 WebSocket 推送到服务端 → 服务端入库、落库离线
→ 服务端推送给用户B会话 → 用户B展示消息
→ 用户B收到（已送达）→ 打开会话已读 → 通知A已读
```

### 5.4 群聊消息收发
```
任一成员发送消息 → WebSocket → 服务端入库
→ 广播给群内其余在线成员 → 离线成员上线后拉取
```

## 6. 功能需求详述

### 6.1 账号体系
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| AC-1 | 手机号注册 | 校验手机号格式与唯一性，密码加密存储（bcrypt） |
| AC-2 | 登录 | 手机号+密码登录，签发鉴权 Token |
| AC-3 | Token 鉴权 | 除注册/登录外接口均需有效 Token，过期自动登出 |
| AC-4 | 退出登录 | 断开 WebSocket，清空本地 Token，服务端作废会话 |
| AC-5 | 用户资料 | 昵称、头像、个性签名；预留 openid 字段（微信登录扩展） |

### 6.2 好友系统
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-1 | 搜索用户 | 支持按手机号/昵称搜索 |
| FR-2 | 添加好友 | 发送好友申请（可附验证消息） |
| FR-3 | 申请处理 | 同意/拒绝；同意后建立双向好友关系 |
| FR-4 | 好友列表 | 展示好友昵称、头像、在线状态 |
| FR-5 | 删除好友 | 删除后解除关系，历史会话保留（单聊仅保留本地） |

### 6.3 会话与聊天
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| CV-1 | 会话列表 | 按最近消息时间倒序，展示最后一条消息预览 |
| CV-2 | 未读计数 | 每个会话未读条数，顶部会话合计未读 |
| CV-3 | 打开会话 | 进入会话页拉取历史消息，清零未读并上报已读 |
| CV-4 | 分页加载 | 历史消息滚动分页（每页 20 条） |
| CV-5 | 单聊会话 | 双人会话，自动创建 |
| CV-6 | 群聊会话 | 群成员可见，广播消息 |

### 6.4 群聊管理
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| GR-1 | 创建群 | 选择成员创建群聊，创建者为群主 |
| GR-2 | 邀请/加入 | 群主/成员可邀请好友入群 |
| GR-3 | 退出群 | 成员退出，群主不可直接退出（需转让或解散） |
| GR-4 | 解散群 | 仅群主可解散，解散后群消失 |
| GR-5 | 改群名 | 群主可修改群名称 |

### 6.5 消息
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| MS-1 | 文本消息 | 纯文本，长度限制 2000 字 |
| MS-2 | 图片消息 | 上传图片，存储后返回 URL，缩略图 |
| MS-3 | 语音消息 | 录音上传，时长、播放 |
| MS-4 | 系统消息 | 「XX 加入了群聊」「XX 退出了群聊」等 |
| MS-5 | 消息状态 | 已发送 → 已送达 → 已读 状态流转 |
| MS-6 | 离线消息 | 离线期间入库，上线后按会话拉取 |
| MS-7 | 消息 ID | 客户端生成唯一消息 ID（UUID）避免重复 |

### 6.6 实时通道
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| RT-1 | 长连接 | WebSocket 长连接，Token 鉴权 |
| RT-2 | 心跳 | 定期心跳保活，超时判定离线 |
| RT-3 | 断线重连 | 断线指数退避重连，重连后拉取遗漏消息 |
| RT-4 | 在线状态 | Redis 维护在线标记，广播给相关好友 |

| --- | --- |

## 9. 验收标准

### 9.1 功能验收
- [ ] 注册、登录、退出全流程可用，Token 鉴权生效。
- [ ] 可搜索并添加好友，申请/同意流程闭环。
- [ ] 可单聊收发文本/图片/语音，状态正确流转。
- [ ] 可建群、邀请、退群、解散，群消息广播。
- [ ] 会话列表未读计数正确，离线消息上线可拉取。
- [ ] 断网重连后消息不丢失、不重复。

### 9.2 性能验收
- 单条文本消息端到端延迟 < 1s（同网段）。
- 连续发送 100 条消息无丢失、无错序。

### 9.3 安全验收
- 未携带 Token 访问受保护接口返回 401。
- 密码不以明文存储。
